# 回放 prompt（逐字）

每个工作区收到同一条消息模板；仅 `<DIR>` 与固定任务文本按场景代入。`a`/`b` 两侧的任务文本逐字相同。

```text
你在本地一个回放 fixture 仓库中作为编码 agent 执行固定任务。规则：

1. 工作目录：<DIR>。所有读写与命令只在 <DIR> 内进行；<DIR> 之外的任何路径都不得修改。
2. 先完整读取 <DIR>/AGENTS.md，它是本仓库的工程 Profile；按其中的优先级执行任务。
3. 不执行任何 git add/commit；不调用真实外部业务系统（为安装依赖访问包注册表除外）。
4. 每运行一条命令，向 <DIR>/RUNLOG.md 追加一行：命令 + 一句原因。
5. 完成后在本地验证能验证的部分，工作区保持最终状态。

固定任务（对所有运行相同）：
<TEXT>

最终消息必须包含：
(a) 变更摘要（文件级）；
(b) 关键决策：命令运行目录与范围、依赖/框架选择、创建的目录或层、依据了 Profile 中哪些约束；
(c) 验证结果（命令与结果）。
```

## 固定任务文本（按场景，逐字）

- s1：新增 `GET /healthz` 端点：返回 200 和 JSON `{"status":"ok"}`。按仓库既有约定实现，并运行仓库的验证入口。
- s2：从零启动这个服务：提供 `GET /items`，返回内存中库存列表的 JSON。保持最小实现，并说明你选择的工具链与验证步骤。
- s3：这个 workspace 中有测试失败。找出失败的测试，修复缺陷，并说明你如何确认修复覆盖了受影响范围。
- s4：这个 Poller 由 server 生命周期持有。修正它的生命周期：可启动、可随 server 干净关闭（不泄漏 goroutine），错误不得被静默丢弃；补一个覆盖关闭行为的测试。
- s5：新增 `GET /books`：query 参数 `page`（默认 1）与 `page_size`（默认 20、上限 100），返回分页响应，响应体用 Pydantic 模型定义；为新增代码补充必要的 docstring 与注释。运行仓库测试。
